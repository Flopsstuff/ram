ram-brain — общий git-бэкапленный «второй мозг» для нескольких AI-агентов на разных машинах.
Сохраняй здесь знания, которые должны пережить одну сессию и быть видны другим агентам:
устойчивые факты, решения, состояние проектов, справочные материалы и заметки.

# Язык

Все заметки пиши по-русски. НЕ переводи технические элементы — оставляй как есть:
пути и имена файлов/папок (projects/, reference/, inbox/, *.md), код, идентификаторы,
команды, URL, названия инструментов, ключи frontmatter.

# Структура и конвенции

- projects/<slug>/            проекты FlopBut / Flopsstuff (overview.md, decisions.md, incidents/, notes/, …)
- paysera/projects/<slug>/    рабочие проекты Paysera
- reference/                  знания, полезные за пределами одного проекта (how-to, грабли, факты)
- machines/                   по заметке на хост
- agents/<id>/                личная папка агента (пишет только он сам)
- linkedin/                   посты LinkedIn, аналитика, tone of voice
- tools/, users/              инструменты; люди
- inbox/                      быстрый захват; позже разложи по дереву.

Правила оформления (frontmatter, теги, ссылки, имена файлов, каркас папок) лежат в
файлах `_conventions.md`: корневой действует везде, файлы в папках добавляют свои правила.
ПЕРЕД записью в папку вызови get_conventions(path) и следуй им. Ответ на write/edit/append
тоже содержит `conventions` — сверь с ними написанное и поправь через edit, если не сходится.

# Правила работы

- Ищи перед записью, чтобы не плодить дубли. По умолчанию поиск семантический
  (mode можно не указывать) — формулируй запрос своими словами, как вопрос.
  Для точных идентификаторов (номера задач вроде FLO-1067, имена файлов, MR,
  коды) добавь mode=keyword — по смыслу они находятся хуже. mode=hybrid не
  используй: на этом vault он ранжирует заметно хуже обоих.
- write = создать; edit = точечная правка (сначала read); rename / move_folder — реорганизация (они чинят ссылки); delete — удаляет.
- Индекс поиска обновляется при каждой записи — никогда не вызывай reindex.
- Пути всегда относительные, например projects/acme/decisions.md.
- Связывай заметки вики-ссылками `[[путь/без-расширения]]` на реальные документы vault
  (например `[[projects/ram/overview]]`). Голый `[[basename]]` резолвится, только если
  файл `basename.md` лежит в корне vault — иначе не резолвится. НЕ ссылайся на слаги из
  локальной памяти агента (`~/.claude/.../memory/`) — в vault их нет. После правок проверяй
  здоровье ссылок через get_outlinks / get_broken_links.
- `exists:false` — это три разных случая, и лечатся они по-разному. Не своди их в один
  список «битых», иначе отчёт становится шумом и настоящие поломки в нём тонут:
  - **дрейф именования** — та же заметка, записанная иначе (`[[user-career-discretion]]`
    при живом `user_career_discretion`). Чинится механически, человеку показывать нечего;
  - **backlog** — ссылка на тему, которую ты сознательно ещё не написал. Это не дефект,
    а пометка «здесь стоит завести заметку». Показывай отдельным списком;
  - **поломка** — переименовали или удалили цель, либо совпадений несколько и надо
    выбрать. Только это заслуживает красного статуса.
  Учти: в веб-интерфейсе GitHub синтаксис `[[...]]` не кликается — это движок mcp-md/Obsidian,
  а не сам git.

Этот инстанс — READ-WRITE.
